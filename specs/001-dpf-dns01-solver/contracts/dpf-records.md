# Contract: DPF 上のレコード配置

**対象**: [../spec.md](../spec.md) の「チャレンジレコードの操作」「ゾーンロックと変更の記録」
「同一チャレンジコードの共有」 / 決定は [../research.md](../research.md) D-01〜D-06, D-10〜D-12

本サービスが DPF のゾーンに対して作る状態の契約。運用者がゾーンを見たときに何が本サービスの
ものかを判別でき、また将来の版が同じ状態を解釈できることを目的とする。

---

## 1. DPF のデータモデルの前提

| 事実 | 帰結 |
|---|---|
| `Record` は **RRset 単位**。NAME + RRTYPE の組み合わせは 1 つだけ | 同名・同種別のレコードを並べられない。メタデータは別の名前に置く |
| `Record.Rdata` は値の配列で **`minItems: 1`** (上限なし) | 1 レコードに複数の RDATA。加除は集合操作になる。**空の RDATA を持つレコードは作れない** |
| `Record.Labels` は key-value のメタデータで **上限 10 件**、値は **1〜63 文字** | **期限の記録をここに置く。**チャレンジコード 1 つにつき 1 キー。DNS には公開されない。排他はゾーンのラベルを使うため、レコードのラベルの枠を消費しない |
| ラベルのキーは `prefix/name` の形。prefix は DNS ドメイン名の形式で最大 253、name は英数字と `.` `-` `_` で最大 63 | prefix に solver の groupName を置き、prefix 一致で自分の記録を判別する |
| `Record.Description` はレコード単位のコメント | 用いない (ゾーン反映側の Description を使う) |
| `PatchRecord` は Ttl / Rdata / Labels / Description を **1 回で更新できる** | RDATA と記録の更新が 1 操作にまとまる |
| `Record.State` は反映状態 | 反映済みは `RECORDSSTATE__0` |
| ゾーン反映は `PatchZoneChanges` (`PatchZoneCommit{Description}`)。`Description` は **最大 80 文字** | 反映のコメントに本サービスの印を付ける |
| `PatchZoneAtomicChanges` は**ゾーン全体の置換** | **直接呼ばない。**`utils.ZoneApplier` 経由でのみ用いる。§5 を参照 |
| ゾーンの `Labels` は key-value のメタデータ (`GetZoneLabels` / `PutZoneLabels`) | **排他の状態が置かれる。**本サービスは直接書かない。§4 を参照 |

## 2. チャレンジレコード

| 属性 | 値 |
|---|---|
| 名前 | `ChallengeRequest.ResolvedFQDN` の正規化名 (`dns.CanonicalName`) |
| 種別 | `TXT` |
| RDATA | チャレンジコードの集合 |

- 名前は **`_acme-challenge` で始まるとは限らない。** CNAME 委譲が使われている場合、
  cert-manager が解決した委譲先の任意の名前になる。名前を縛らない。
- 本サービスは**自分のチャレンジコードに対応する RDATA のみ**を加除する。
  同名のレコードに本サービス以外が置いた RDATA (SPF、ドメイン所有確認など) があれば、
  追記時も削除時も維持する。
- **既存レコードに追記する場合、TTL を変更しない。** TTL を定めるのは新規作成時のみ。
  TTL は `nullable` であり、null は「ゾーン既定を継承」を意味する。0 は `minimum: 1` に
  反して不正である。null を 0 として扱ってはならない。
- RDATA が 1 つも残らなくなる場合はレコードごと削除する。`RecordsRdata` の `minItems` が
  1 であり、**RDATA が空のレコードは API が受け付けない。**

## 3. 期限の記録 (チャレンジレコードのラベル)

記録は**チャレンジレコード自身のラベル**に置く。**別のレコードは作らない。**
ラベルは DPF のレコードに付く key-value のメタデータであり、**DNS には公開されない。**

**チャレンジコード 1 つにつきラベル 1 つ。保持者を区別しない。**

```
expire.acme.dns-platform.jp/<対象の識別値>  =  <期限 (UTC Unixtime)>
```

| 部分 | 内容 | 長さ | API 上の制約 |
|---|---|---|---|
| キーの prefix | `expire.acme.dns-platform.jp` | 27 | DNS のドメイン名の形式、最大 253 |
| キーの name | 対象の識別値 | 16 | 英数字と `.` `-` `_`、最大 63 |
| 値 | 期限 (UTC Unixtime) | 10 | 英数字と `.` `-` `_` / `minLength: 1`, `maxLength: 63` |

**対象の識別値**: `SHA-256(チャレンジコード)` の先頭 64 ビット、16 進小文字 16 文字。

```
_acme-challenge.example.jp   TXT  "<コードA>" "<コードB>"
                             labels:
                               expire.acme.dns-platform.jp/<H(コードA)> = 1790000000
                               expire.acme.dns-platform.jp/<H(コードB)> = 1790001800
                               spf-managed-by                          = someone-else  ← 他者のラベル。維持する
```

**自分の記録の判別は prefix の一致で行う。** prefix は本プロジェクトが管理する DNS 名で
あり、利用者が同じ prefix を使うことは実質的にない。

**版の扱い**: キーに版を含めない。**記録は期限で自然に消えるため、版を変えたい場合は
prefix を変えればよい。** 古い prefix の記録は誰も更新しなくなり、期限の経過後に回収される。

### 回収 (掃除)

**`Present` と `CleanUp` の双方で、処理の最初に行う。**

ダイジェストは可逆でないため、キーからチャレンジコードを復元できない。
**レコード内の各 RDATA の値から識別値を計算し、ラベルのキーと突き合わせる。**

| 状況 | 扱い |
|---|---|
| RDATA があり、対応するラベルが期限切れ | **両方を取り除く** |
| RDATA があり、対応するラベルが期限内 | 残す |
| RDATA があるが、対応するラベルが無い | **取り除かない** (本サービス以外の値でありうる) |
| ラベルが期限切れで、対応する RDATA が無い | ラベルを取り除く |

回収の結果 RDATA が 1 件も残らない場合は、レコードごと削除する
(`RecordsRdata` の `minItems` が 1 であるため)。

**常時動く回収処理を設けてはならない (MUST NOT)。** 回収は `Present` / `CleanUp` の
内部でのみ行う。**当該の名前に対する操作が二度と来なければ回収されない**ことは許容する。

### 提示と後片付け

| 操作 | 行うこと |
|---|---|
| `Present` | 回収 → 当該コードの RDATA を追加 (既にあれば追加しない) → ラベルが無ければ追加。**残りが閾値以上なら値を更新しない** |
| `CleanUp` | **回収のみ。**当該コードの RDATA とラベルを削除してはならない (MUST NOT) |

**望む最終状態が現状と一致する場合、ゾーンへの変更を行ってはならない (MUST NOT)。**
排他の取得も反映も行わない。**変更 API は 0 回**で済む。

| 条件 | `Present` | `CleanUp` |
|---|---|---|
| 回収すべき期限切れがある | 変更する | 変更する |
| 当該コードの RDATA が無い | 変更する | — |
| 当該コードのラベルが無い | 変更する | — |
| ラベルの残りが閾値を下回る | 変更する | — |
| 上記のいずれでもない | **変更しない** | **変更しない** |

閾値は猶予の 1/2 (既定 30 分)。

**この規則は再試行への配慮である。** 同一ゾーンへのレコード操作は並行できないため、
変更が不要な操作に反映を費やすと、再試行が重なった際に直列の待ち行列を作る。
再試行の時点では元の提示が設定した期限がそのまま残っており、更新しても窓はほとんど
前進しない。

要否の判定は排他を取らずに公開レコードを読んで行ってよい (MAY)。判定の結果が「不要」で
あれば何も変更しないため、読み出しの時点の状態が古くても害がない。
**ラベルの残りが閾値以上であれば、その RDATA が他の実行に回収されることもないため、
判定と実行の間に状態が変わる経路がない。**

### 他者のラベルの保全

`PatchRecord` の `Labels` は**マップ全体を置き換える。** したがって現在のラベルを読み出し、
**prefix が `expire.acme.dns-platform.jp/` のキーのみ**を加除して書き戻す。
**prefix に一致しないキーは必ず維持する。**

### 件数の上限

ラベルは 1 レコードあたり **10 件** (`RecordLabels.maxProperties`)。この枠は本サービス以外が
付けたラベルと共有する。追加によって総数が 10 を超える場合、**要求を失敗させ、ログに
記録する。** 他者のラベルも本サービスの記録も追い出さない。

到達する経路は、**同一の名前に対する検証の失敗が繰り返され、そのたびに新しい
チャレンジコードが払い出される場合**である。猶予の長さが直接効くため、猶予を短く保つ
(既定 1 時間)。

### 記録にトークンを含めない

キーはダイジェスト、値は時刻である。アクセストークン、およびチャレンジコードそのものを
復元できる値を含まない。

## 4. ゾーンロック

`dpf-go` (v0.6.0) の `utils.Mutex` に委ねる。本サービスはゾーンのラベルを直接書かない。

| ラベルキー | 値 |
|---|---|
| `lock.dpf-go` (ゾーンのラベル) | `<ロックオーナー>-<奪取可能時刻 (UTC Unixtime、10 桁)>` |

ロックオーナーは **1〜32 文字** (`dpf-go` の上限。超えると `ErrOwnerTooLong`)。
文字種はラベルの値の共通ルールに従い、英数字と `.` `-` `_` に限る。

| 性質 | 内容 |
|---|---|
| 実現原理 | ゾーンのラベルに保持者と奪取可能時刻を書く。読み取りから書き込みまでの区間を、一時レコード (`_dpf-go-lock`) の追加の重複拒否で排他する |
| 取得の費用 | 一時レコードの作成 → ゾーンのラベルの書き込み → 一時レコードの取り消し。**いずれも完了を読み戻しで待つ** |
| 解放 | ゾーンのラベルの奪取可能時刻を現在時刻へ更新する。**完了を待たない** |
| ラベルの消費 | **ゾーンのラベルを 1 つ恒久的に消費する** (解放後も残る)。ゾーンのラベルが上限に達していれば `ErrLabelLimit` |
| ゾーン反映との関係 | **影響しない。**一括置換と反映の後も排他は保持され、通常どおり解放される |
| TTL | **既定 2 分** (`dpf-go` の既定 15 分から短縮)。`Apply` は実行中に自動で延長するため、操作が長引いても失効しない |
| 期限内の他者の排他 | 取得できない (`ErrStillLock`)。**奪わない**。`WithLockWait` で待つ |
| 期限切れのロック | 奪取する。保持者の消滅でゾーンが恒久的にロックされるのを防ぐため |
| 再入 | **できない。**保持中の再取得は `ErrStillLock` |
| 2 者の同時取得 | **起こらない。**一時レコードの重複の拒否は編集者に依らないため、ユーザ (アクセストークン) をまたいで効く |
| 保持中の他ユーザ・管理画面からの編集 | **止められない。**保持中の尊重は協調的である。ここは割り切る |
| 旧版 (v0.5.0 以前) との混在 | **排他が成立しない。**旧版は SOA のラベルを見るため。同じゾーンを触るプログラムはまとめて更新する |

**プロセス内での直列化は不要。** 同一のアクセストークンを用いる複数の実行の間でも排他が
成立する。`NewMutex` ごとに owner が異なり、`Lock` は再入できない。
`Unlock` と `Renew` は保持者の確認を伴う。

## 5. 変更の手順

`utils.ZoneApplier.Apply` に委ねる。

| # | 操作 | 変更 API | 完了を待つ |
|---|---|---|---|
| 1 | `ResolvedZone` と一致する DPF のゾーンを特定する (`utils.GetZoneFromName` の結果の名前が `ResolvedZone` と一致することを確かめる。longest match の結果をそのまま使わない。D-18) | | |
| 2 | `domainFilters` を判定する。一致しなければ**何も変更せず失敗** | | |
| 2a | **変更の要否を、排他を取らずに公開レコードを読んで判定する** | | |
| 2b | 望む最終状態が成立していれば**ここで終える。変更 API は 0 回** | | |
| 3 | `ZoneApplier.Apply` を呼ぶ | | |
| 3a | └ 排他を取得する (一時レコードの作成・ゾーンのラベルの書き込み・一時レコードの取り消し)。`WithHoldOptions(WithLockWait(d))` で待つ | ○ ×3 | ○ ×3 |
| 3b | └ 公開レコードを取得する (`GetRecordCurrents`) | | |
| 3c | └ 編集関数で期限切れを回収し、`Present` なら Rdata とラベルを加除する。**変更が不要と判明すれば `utils.ErrSkipApply` を返す** | | |
| 3d | └ 一括置換と反映 (`PatchZoneAtomicChanges`)。3c で省略した場合は行わない | ○ | ○ |
| 3e | └ 排他を解放する (ゾーンのラベルの書き込み) | ○ | |

変更 API の回数は `dpf-go` の実装で決まり、本サービスは制御しない。
**1 回の処理が要求のタイムアウト (60 秒) を越えることを前提とする。** 処理は操作期限
(既定 5 分) まで続き、再試行は 2b または 3c で変更不要と判定されて成功する。

### 編集関数の責務

編集関数は `[]dpf.OverwriteRecordsInner` を受け取り、同じ型を返す。

- **対象のレコード以外は、受け取った要素をそのまま返す。**
  Name / Ttl / Rrtype / Rdata / Description / Labels がすべて引き継がれるため、
  そのまま返せば失われない。
- **処理の最初に期限切れを回収する。** 各 RDATA の値から識別値を計算し、期限切れの
  ラベルと突き合わせる。対応するラベルを持たない RDATA は取り除かない。
- `Present` の場合のみ、当該コードの RDATA を追加し (既にあれば追加しない)、
  ラベルの値を「現在時刻 + 猶予」へ更新する。**`CleanUp` は回収しか行わない。**
- RDATA が 1 件も残らない場合は、**当該レコードを一覧から除いて返す。**
  `RecordsRdata` の `minItems` が 1 であり、空の RDATA を持つレコードは返せない。
- 期限切れの記録の回収は、この中で行う (メモリ上の操作であり API を要さない)。
- 書き込む対象を組み立てる直前に、`domainFilters` の判定を再度確認する。
- **回収と加除の結果が受け取った一覧と変わらない場合は、`utils.ErrSkipApply` を返す。**
  一括置換と反映が省略され、ゾーンのシリアルと履歴が動かない。空の一覧を返しては
  ならない (`ErrNoRecords` として失敗する)。`ErrSkipApply` を他のエラーと `errors.Join` で
  包んではならない (省略が優先され、もう一方が失われる)。
- context が打ち切られている場合は `ErrSkipApply` ではなく `ctx.Err()` を返す。
- **SOA と Zone Apex の NS は触れない。** 取り込まれないため内容に影響しないが、
  編集関数が誤って改変しないよう対象から除く。

### 禁止

- **`PatchZoneAtomicChanges` を直接呼んではならない (MUST NOT)。**
  `overwrite_soa` と `overwrite_zone_apex_ns` の**既定は `true`** であり、公開レコードから
  組み立てたリクエストをそのまま送ると SOA と Zone Apex の NS が意図せず置き換わる。
  `ZoneApplier` は常に `false` を送る。
- 排他の一時レコード (`_dpf-go-lock`) を本サービスが操作してはならない (MUST NOT)。
  権威サーバへ公開された場合の回復はライブラリが行う。
- **`utils.WithLocker` で排他を差し替えてはならない (MUST NOT)。** 既定の排他は、
  2 者の同時取得を DPF-API の重複の拒否によってユーザをまたいで防ぐ。外部の仕組み
  (etcd など) に替えると、その仕組みを使うプログラム同士でしか防げなくなる。

### 中断したとき

`Apply` は取得・編集・置換を 1 つの呼び出しで行い、**編集中の状態を経由しない。**
中断した場合、live なゾーンは無変更のまま残る。積んだ変更の破棄は不要である。

適用の途中で排他を他者に奪われた場合、編集関数へ渡された context が打ち切られ
`ErrNotLockHolder` が返る。**保護が切れたまま書き込むことはない。**

反映が完了したのちに解放だけが失敗した場合も、`Apply` はエラーを返す。本サービスは
これを要求の失敗として返す。排他は TTL の満了で失効し、再試行は変更不要と判定されて
成功する。

## 6. ゾーン反映のコメント

`PatchZoneCommit.Description` に次を設定する。

```
by cert-manager(<ロックオーナー>)
```

固定部 `by cert-manager()` は 17 文字。ロックオーナーの上限は 32 文字 (§4) であり、
最大 49 文字で `Description` の `maxLength` 80 に収まる。この形式以外を付与しない。切り詰めない。
ゾーン名・レコード名・レコード値・トークンを含めない。
